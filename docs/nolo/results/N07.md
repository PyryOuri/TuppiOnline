# N07 — The coverage screen: the framing does propose new, priced decisions

Task status: **COMPLETE**. Scientific outcome: **GO** on the feasibility gate,
with the soundness gate passed on every position. The fixed bank finished in
78.8 minutes against a four-hour cap. Date: 2026-09-06.

Preregistration: [`docs/nolo/hypotheses.md`](../hypotheses.md), written before
any deal of the screen bank was generated.

## What was asked and what came back

Does the N04 security framing ever propose a *verified, score-relevant* departure
from what the baseline plays, on deals the implementation has never seen? On 256
new deals it did so in **13 distinct deals** — seven UNIVERSAL and six
SECURITY_ONLY — against a preregistered threshold of five. Nothing failed the
soundness gate.

This is a position screen along a fixed reference trajectory. It is **not**
evidence of a playing-strength improvement, and 13 deals in 256 is not an
estimate of a useful population rate. It answers only whether building the N08
adapter has something to act on.

The two label families behave exactly as N05 defined them. A UNIVERSAL row's
certified upper bound sits at or below the baseline's all-continuation lower
bound with a strictly better case available — deal 164 guarantees 7 where the
baseline can reach 8. A SECURITY_ONLY row improves only the worst case under the
stated control model — deal 174 caps at 10 where the baseline can reach 11, but
its own best case is worse than the baseline's, so it promises nothing against
an opponent who errs.

Deal 91 is worth reading twice. The candidate guarantees exactly 4 while the
baseline ranges over 3–5. The baseline's *best* case is better. The claim is
SECURITY_ONLY precisely because it is a worst-case improvement bought at the
cost of the upside, and the label refuses to pretend otherwise.

## The soundness gate — PASS

Zero on every check, across all 1,785 eligible positions:

| Check | Failures |
| --- | ---: |
| false certificates | 0 |
| illegal choices | 0 |
| information leaks | 0 |
| continuation violations | 0 |
| true layout outside the enumerated support | 0 |

The last of these is the sharpest one available and is worth naming explicitly.
A certificate quantifies over a support asserted to be complete. If the layout
actually being played were not in that support, the support was not complete and
every guarantee derived from it would be void. The harness reads the real hands
from the private state **after** the decision and checks membership. It held at
every resolved position, on both banks.

Each of the 13 deviations was additionally re-verified by a second, independent
N03 run from the certificate alone, on its own budget, and had to reproduce the
same terminal set. All 13 did.

## The development bank, and what it is not

`nolo-info-dev-v1` indices 0–63 were run first, as the task permits, to find
harness bugs before the screen was locked: 452 eligible positions, zero soundness
failures, 5 score-relevant deviations in 4 deals, 20.6 minutes. Two defects
surfaced there and were fixed before locking — score-state pairs serialised as
Python tuples rather than JSON arrays, and the independent re-verification
running on every position instead of on the deviations the task asks be
re-verified.

Its counts are a debugging artefact. They are not an estimate of the screen's
rate and carried no weight in the gate, which was decided on the screen bank
alone. The screen bank was never used to choose a feature, a cap or a seed.

## Limitations

The trajectory is the baseline's throughout: a proposed action is recorded and
then discarded, and play continues with what v2 chose. So this measures *how
often a certified better decision exists at a position v2 actually reaches*, not
what would happen if the candidate played the deal. Whether executing these plans
changes results is N08's and N09's question, and nothing here anticipates it.

The scope is the last three tricks, at most 100 worlds, one scoreboard `(0,0)`,
one contract, and one reference policy. 372 eligible positions — 21% — were left
unresolved by those limits and are reported as such rather than excluded. Any
rate quoted from this screen is a rate under exactly those conditions.

No significance test was applied and none is appropriate: this is a bounded
discovery and feasibility screen, and a proportion from it carries no inferential
claim.
