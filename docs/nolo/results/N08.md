## What was built

[`src/tuppi_nolo/adapter.py`](../../../src/tuppi_nolo/adapter.py) —
`SecurityCertifiedNoloPolicy`, a subclass of the actual v2 policy
(`VoidSeekingPartnerAwarePolicy`) living in the research layer. Showing, RAMI,
out-of-range NOLO and every unresolved decision delegate to v2 unchanged, so it
can only differ where an exact, verified answer exists.

The preference is expressed the way every Phase 4 policy expresses one: a named
component on **every** legal action, above the inherited vector, with v2's
ranking surviving underneath as the tie-break. The chosen action is the
lexicographic maximum, so `choose_action`, `decide` and `explain` read the same
ranking and cannot disagree. No catalogue rule and no validation provenance was
added to Phase 4; the rule ids are the inherited ones, exactly as `void_lead`
does it.

## The one design decision that matters

**The component's value is N05's worst-case score-state proxy, not a trick
count.** That single choice is what makes the scoreboard behaviour fall out
instead of being special-cased: two actions that differ by a trick but price to
the same score state get the *same* component value, the tie falls through to
v2, and the baseline survives untouched.

So the whole of N05's scoreboard table reproduces through the policy, with no
branch anywhere in the file that mentions a score:

| Witness | `(0,0)` | Team 0 up `(40,0)` | Team 0 down `(0,40)` |

| A | **8S** UNIVERSAL | QD — baseline kept | **8S** UNIVERSAL |
| B | **9C** SECURITY_ONLY | **9C** SECURITY_ONLY | 3C — baseline kept |

## Honouring the continuation

A security value is only attained if the whole certified plan is played. Taking
`9C` and then reverting to the baseline's next card is not a weaker guarantee; it
is no guarantee at all. So when the adapter **corrects** the baseline it retains
the complete verified plan, indexed by information key, and later own decisions
replay it with no further search.

Completeness is not assumed. N03 rejects a plan that fails to name an action at
any reachable own node, so a verified certificate *is* the reservation required
before the first card is committed. The test that proves the point replaces
`solve_security` with a function that raises, and B still plays `3C`.

The plan is retained **only** where a correction has to be honoured. An unchanged
action corrects nothing, needs no future restriction, and leaves v2 driving —
which keeps the adapter's divergence from v2 confined to exactly the decisions it
actually claims something about.

A history the plan does not own drops the plan, and says so
(`nolo_fallback_plan_history_mismatch`), rather than playing on under a stale
certificate. A new deal clears everything.

This is therefore a **finite-memory research strategy**, not a stateless Phase 4
policy, and it is documented as one. Its memory holds only its own earlier
observations and the plans it verified from them. No hidden hand, no real deal
and no partner's private state can enter it: `solve_security` refuses anything
that is not a `PlayerObservation`.

Each seat runs its own instance and reads only its own observation. The control
model quantifies over arbitrary partner actions, which is what makes that legal —
there is no shared team controller here and must never be one.

## The cross-check that carries the most weight

The adapter was run over N07's completed position list and its decisions compared
to the screen's, position by position:

| | Screen (N07) | Adapter (N08) |
| --- | ---: | ---: |
| positions | 1,785 | 1,785 |
| resolved | 1,413 | 1,413 |
| corrections / deviations | 13 | 13 |
| distinct deals | 13 | 13 |
| UNIVERSAL / SECURITY_ONLY | 7 / 6 | 7 / 6 |

The correction set is **identical** — same deal, seat and trick, same card, same
claim label — and every position resolves or fails to resolve identically. The
analysis path and the policy path are two independent routes to the same answer,
and they agree on all 1,785. Any disagreement here would have been FAILED_CHECK
regardless of how a simulation looked.

## Offline cost report

Measured memoryless — a fresh adapter at every position — so what is timed is the
expensive case: a first decision that builds a support, searches it and verifies
the certificate. Plan replay costs a dictionary lookup and is deliberately not
folded in, where it would flatter these numbers.

| | p50 | p95 | max |
| --- | ---: | ---: | ---: |
| latency, all positions | 1.61 s | 164.3 s | 285.7 s |
| latency, resolved only | 3.00 s | 135.7 s | 285.7 s |
| search engine transitions | 1,140 | 45,696 | 97,560 |
| verification engine transitions | 702 | 11,460 | 30,840 |
| plan size on a correction | 90 | 1,120 | 1,120 |

Fallback rate **20.8%** (372 of 1,785), every one of them
`nolo_fallback_search_unresolved` — the same 100-world / 100,000-transition
ceiling that left 21% of N07 unresolved. No position fell back for an unverified
certificate or a plan mismatch. The 256 deals took 74.9 minutes across ten
worker processes.

**This is an offline cost report and nothing more.** A p95 of 164 seconds per
decision is not a claim of suitability for the live server, and the task does not
require one.

## Limitations

The guarantee is relative to one stated baseline and one control model in which
the partner is adversarial. SECURITY_ONLY promises nothing against an opponent
who errs. The scope is the last three tricks, at most 100 worlds, and one
contract; one decision in five is left to v2 because the budget could not resolve
it, and the adapter claims nothing at all about those.

Reproducing the screen is a consistency result, not a playing-strength result.
Whether executing these plans changes outcomes is N09's question, and nothing
here anticipates it.
