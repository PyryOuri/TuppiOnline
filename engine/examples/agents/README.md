# Phase 4 baseline-agent examples

Every artifact here is canonical JSON, regenerated by

```bash
PYTHONPATH=src python examples/agents/generate_examples.py
```

and checked against the code by `tests/agents/`. All of them are CI-sized.

| File | Contents |
| --- | --- |
| `strategy_rule_catalogue.json` | Every strategy rule with its stable ID, contract, phase, condition, action preference, provenance, rationale, limitations, and implementing profiles. |
| `heuristic_profiles.json` | The eight registered profiles with their parameters, enabled and disabled rules, and content-addressed identities. |
| `phase4_agents.json` | The immutable agent specifications and the registered partnerships. |
| `ladder_fixed_deal.json` | One fixed deal played by each ladder rung, with the contract, tricks, and points each produced. |
| `decision_diagnostics.json` | Three real decisions with their full candidate rankings, cited rules, and reason codes. |
| `legacy_port_compatibility.json` | 332 curated positions where the port and the frozen Archive agree, plus the two documented showing deviations. |

## Obtaining an action from each strategic agent

```python
from tuppi_agents import construct_agent, phase4_specifications_by_profile_key
from tuppi_engine import ExplicitDeal, begin_explicit_deal, create_match, match_observation_for
from tuppi_rules import MatchScore

specifications = phase4_specifications_by_profile_key()
state = begin_explicit_deal(
    create_match(initial_score=MatchScore(), initial_dealer=0, match_ref="demo"),
    ExplicitDeal(dealer=0, hands=hands),
)
seat = state.current_actor
observation = match_observation_for(state, seat)

for key in ("legacy_heuristic_port_v1", "reactive_contract_v1", "public_counting_v1",
            "partner_aware_v1", "match_aware_v1"):
    agent = construct_agent(specifications[key], seat=seat)
    print(key, agent.choose_action(observation))
```

## Viewing structured diagnostics

```python
decision = agent.decide(observation, diagnostics=True)
for candidate in decision.diagnostics.candidates:
    print(candidate.action, candidate.score_vector, candidate.reason_codes)
```

`choose_action` never builds a diagnostics record, and `decide` computes the
identical ranking, so switching diagnostics on cannot change play.

## Running a fixed deal from the command line

```bash
PYTHONPATH=src python -m tuppi_agents.runner play-deal \
  --deal-file examples/engine/project_target_v1/valid_one_deal_match.json \
  --profile match_aware_v1 \
  --output /tmp/ladder-result.json \
  --diagnostics /tmp/ladder-diagnostics.json

PYTHONPATH=src python -m tuppi_agents.runner explain \
  --deal-file examples/engine/project_target_v1/valid_one_deal_match.json \
  --profile partner_aware_v1 \
  --output /tmp/first-decision.json
```

## Running a heterogeneous partnership

```python
from tuppi_agents import construct_agent, phase4_specifications_by_profile_key
from tuppi_engine import play_active_deal

specifications = phase4_specifications_by_profile_key()
agents = (
    construct_agent(specifications["match_aware_v1"], seat=0),
    construct_agent(specifications["reactive_contract_v1"], seat=1),
    construct_agent(specifications["partner_aware_v1"], seat=2),
    construct_agent(specifications["legacy_heuristic_port_v1"], seat=3),
)
state = play_active_deal(state, agents)
```

Every seat must receive a distinct runtime object; the engine rejects a shared
one.

## Running baseline cross-play and reproducing the Phase 4 report

```bash
PYTHONPATH=src python -m tuppi_agents.runner run-suite \
  --bank-dir banks --output-dir runs/phase4 \
  --report reports/phase4/baseline_report.json --only crossplay

PYTHONPATH=src python -m tuppi_agents.runner run-suite \
  --bank-dir banks --output-dir runs/phase4 \
  --report reports/phase4/baseline_report.json --only all
```

The full suite takes tens of minutes and is resumable: completed atomic shards
in `runs/` are reused rather than replayed. `runs/` is git-ignored; the committed
artifact is the report.
